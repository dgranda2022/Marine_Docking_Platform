# Marine Docking Platform - Engineering Design 2 (ED2)

**Project:** Active Stabilization System for Marine Docking  
**Hardware:** Jetson Orin Nano, CubeMars AK60-39 Motors, BNO085 IMU  

This repository contains the control logic, hardware drivers, and data visualization scripts for the active stabilization docking platform. Please read this entire guide before modifying code or connecting to the hardware.

---

## Section 1: Jetson Hardware Constraints & Setup

**The Jetson Orin Nano acts as an offline execution brain.** It is pre-configured with all the necessary Python dependencies (`adafruit-circuitpython-bno08x`, `busio`, `python-can`, etc.). 

⚠️ **CRITICAL NETWORK WARNING:** The Jetson does **not** have internet access when connected via USB-C. 
* Do **not** run `sudo apt update`, `sudo apt upgrade`, or `pip install`. They will hang and fail.
* Do **not** attempt to connect the Jetson to the Eduroam Wi-Fi network. 
* If you need a new package installed or a GitHub repo pulled directly to the Jetson, ask the Controls Lead (Daniel). It requires a native Linux PC to establish a network bridge and share internet.

---

## Section 2: Connecting to the Jetson (Headless)

When you need to test your code on the physical hardware, you will connect to the Jetson via the USB-C data cable. The Jetson acts as a local network device at `192.168.55.1`.

**1. Plug in the USB-C cable** from the Jetson to your laptop.
**2. Open your terminal:**
* **Windows:** Open PowerShell (or WSL).
* **Mac:** Open the Terminal app.
* **Linux:** Open your standard terminal.
**3. Run the SSH command:**
```bash
ssh edg5@192.168.55.1

```

*(If prompted with a security warning about the host key, type `yes`. Ask Daniel for the password if you don't have it).*

## Section 3: Development Framework & Git Workflow

To prevent hardware crashes and code conflicts, we use a strict "Develop Locally, Test Remotely" workflow.

### 1. Initial Setup

Clone the repository to your **local laptop** (inside WSL if you are on Windows, or natively on Mac/Linux):

```bash
git clone [https://github.com/dgranda2022/Marine_Docking_Platform.git](https://github.com/dgranda2022/Marine_Docking_Platform.git)
cd Marine_Docking_Platform

```

### 2. The Golden Rule of Git

🚨 **DO NOT PUSH TO THE MAIN BRANCH.** 🚨
Before you write any code, create your own feature branch:

```bash
git checkout -b feature/your-name-task

```

### 3. Writing and Testing Code

1. Edit your code locally on your laptop using VSCode.
2. When you are ready to test on the hardware, **create a personal folder on the Jetson** so you don't overwrite the working master scripts.
*(Over SSH)*: `mkdir ~/your_name_test`
3. Push your script from your laptop to the Jetson using `scp`:
```bash
scp my_script.py edg5@192.168.55.1:~/your_name_test/

```


4. SSH into the Jetson, navigate to your folder, and run your script.

### 4. Pushing for Review

If your code runs successfully on the physical hardware, push your branch to GitHub and create a Pull Request (PR) to merge it into `main`:

```bash
git add .
git commit -m "Added PID controller logic"
git push origin feature/your-name-task

```

## Section 4: Validated Codebase & Usage

There are several older scripts in this repository, but **only the scripts listed below are validated and guaranteed to work.** Use these as templates for creating the final controller, as they contain the correct I2C `busio` configurations and CAN bus IDs.

### On the `main` branch (Runs on the Jetson):

* `imu_test.py`: Initializes the BNO085 IMU, reads the Roll/Pitch/Yaw data, prints it to the console, and logs it to a timestamped `.csv` file. Use this to understand how to pull data from the sensor.
* **Usage:** `python3 imu_test.py`



### On the `laptop_station` branch (Runs on the Ground Station PC):

* `motor_driver.py`: Connects to the CubeMars AK60-39 motor over the CAN bus (ID 1), sends torque commands, reads positional feedback, and logs the performance to a `.csv` file.
* **Usage:** Requires a Linux PC with the CAN adapter configured. Run `python3 motor_driver.py`.


* `imu_test_plotter.py`: Post-processing script. Reads the CSV files generated by the Jetson's IMU test and uses `matplotlib` to graph the platform's roll over time.
* `plot_motor_data.py`: Post-processing script. Reads the CSV generated by the motor driver and graphs the Command Torque vs. Actual Torque and Position.

### Next Steps / Capstone Goals:

You can use `motor_driver.py` and `imu_test.py` as your building blocks. Make sure you understand how to individually read the IMU and individually command the motor before attempting to merge them into a closed-loop PID controller.
